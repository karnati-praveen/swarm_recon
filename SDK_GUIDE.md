# ROS 2 & MAVLink SDK Integration Architecture Guide

## 1. Executive Summary & Overview
The `swarm_recon` package provides a commercial-grade, decentralized swarm intelligence engine capable of autonomous Voronoi area search, rotational APF threat evasion, and target-triggered encirclement handoff ("Hunter-Killer" mode). This guide details the architectural blueprint for integrating `swarm_recon` with ROS 2 middleware and PX4 / ArduPilot MAVLink v2 autopilots.

To comply with strict installation size constraints (<500MB total dependency footprint, Requirement R3), the integration layer is designed around duck-typing adapters and standard-library fallback mocks. This eliminates mandatory heavy binary dependencies (`rclpy`, `pymavlink`) while supporting native ROS 2 and MAVLink bindings when present in the host environment.

## 3. ROS 2 Node Architecture (`SwarmReconROS2Node`)

### 3.1 Node & Namespace Conventions
- **Node Naming**: `swarm_recon_node_{drone_id}` (e.g. `swarm_recon_node_0`, `swarm_recon_node_1`)
- **Namespace**: `/drone_{id}` (e.g. `/drone_0`, `/drone_1`)
- **Loop Execution Rate**: 10 Hz ($\Delta t = 0.1\text{s}$), synchronized with `SimulationConfig.dt`.

### 3.2 Quality of Service (QoS) Policies
- **State Telemetry (`~/telemetry`)**: Best Effort, Volatile, Depth 10. High-frequency, loss-tolerant spatial state streaming.
- **Peer Telemetry (`~/peer_telemetry`)**: Best Effort, Volatile, Depth 10. Ingress state heartbeats from peer drones.
- **Target Found (`~/target_found`)**: Reliable, Transient Local, Depth 10. Critical event broadcast when a target is detected.
- **Target Broadcast (`~/target_broadcast`)**: Reliable, Transient Local, Depth 10. Subscribes to peer target discovery events.
- **Threat Zones (`~/threat_zones`)**: Reliable, Transient Local, Depth 10. Dynamic circular hazard boundary updates.

### 3.3 Topic & Message Specifications Table
| Topic Name | Direction | Message Type | QoS | Description |
|------------|-----------|--------------|-----|-------------|
| `~/telemetry` | Publish | `geometry_msgs/msg/PoseStamped` | Best Effort | 10 Hz spatial pose, velocity vector, heading, active status |
| `~/nav_waypoint` | Publish | `geometry_msgs/msg/PoseStamped` | Reliable | Navigation waypoint generated by search or encirclement |
| `~/target_found` | Publish | `geometry_msgs/msg/PointStamped` | Reliable | Target detection telemetry payload broadcast |
| `~/peer_telemetry` | Subscribe | `geometry_msgs/msg/PoseStamped` | Best Effort | State heartbeats from peer drones in the swarm |
| `~/target_broadcast` | Subscribe | `geometry_msgs/msg/PointStamped` | Reliable | Peer target detection events triggering mode switch |
| `~/threat_zones` | Subscribe | `geometry_msgs/msg/PoseArray` | Reliable | Dynamic circular threat zone positions and radii |

### 3.4 Telemetry JSON Payload Schema
```json
{
  "drone_id": 0,
  "position": {"x": 12.5, "y": 24.3, "z": 10.0},
  "velocity": {"vx": 1.2, "vy": -0.5, "vz": 0.0},
  "heading": 0.38,
  "active": true,
  "sector_id": 0,
  "last_heartbeat": 12.4,
  "mode": "VORONOI_SEARCH"
}
```

## 4. MAVLink PX4 & ArduPilot Integration (`MAVLinkBridge`)

### 4.1 System IDs & Component IDs
- **Transport**: MAVLink v2 over UDP socket (`udp:127.0.0.1:14540` for SITL instance 0, port `14540 + id`) or Serial (`/dev/ttyAMA0`, 57600/115200 baud).
- **Autopilot Target System ID**: `drone_id + 1` (e.g. Drone 0 -> System ID 1)
- **Autopilot Component ID**: `MAV_COMP_ID_AUTOPILOT1` (1)
- **Companion Computer Source System ID**: `drone_id + 1` (or `100 + drone_id`)
- **Companion Computer Component ID**: `MAV_COMP_ID_ONBOARD_COMPUTER` (191)

### 4.2 Key MAVLink Message Definitions
1. **`HEARTBEAT` (#0)**:
   - Broadcast at 1 Hz (`type = MAV_TYPE_ONBOARD_CONTROLLER` = 18, `autopilot = MAV_AUTOPILOT_INVALID` = 8). Maintains companion computer liveness on the autopilot bus.
2. **`MAV_CMD_NAV_WAYPOINT` (#16)** via `COMMAND_LONG` (#76) / `MISSION_ITEM_INT` (#39):
   - Command ID: 16
   - Param 1 (Hold Time): 0.0s
   - Param 2 (Acceptance Radius): 1.0m
   - Param 3 (Pass Radius): 0.0m
   - Param 4 (Yaw Angle): Target heading in radians
   - Param 5 (Local X / North): `target_y` (Swarm Y -> NED North)
   - Param 6 (Local Y / East): `target_x` (Swarm X -> NED East)
   - Param 7 (Local Z / Down): `-altitude` (-10.0m)
 3. **`SET_POSITION_TARGET_LOCAL_NED` (#84)**:
   - Coordinate Frame: `MAV_FRAME_LOCAL_NED` (1)
   - Bitmask `type_mask`: `0b0000101111000000` (`0x0BC0`, Position + Velocity + Yaw enable)
   - Positions: $(X_{NED}, Y_{NED}, Z_{NED})$
   - Velocities: $(V_{x,NED}, V_{y,NED}, V_{z,NED})$
   - Frequency: 10 Hz for continuous Offboard / Guided flight control.
 4. **`LOCAL_POSITION_NED` (#32)** (Ingress Feedback):
   - Feedback coordinates $(x_{ned}, y_{ned}, z_{ned})$ and velocities $(vx_{ned}, vy_{ned}, vz_{ned})$ parsed to update local `SwarmAgent` position estimates.

### 4.3 Autopilot Dialect Differences
- **PX4 Autopilots**: Require `OFFBOARD` mode. PX4 mandates a continuous stream of `SET_POSITION_TARGET_LOCAL_NED` messages at >= 2 Hz for at least 0.5s *prior* to engaging `OFFBOARD` mode, otherwise the flight mode switch command is rejected.
- **ArduPilot Copter**: Operates in `GUIDED` mode. Accepts discrete `COMMAND_LONG` (`MAV_CMD_NAV_WAYPOINT`) or continuous streaming `SET_POSITION_TARGET_LOCAL_NED` messages.

## 5. Coordinate Transformations & Telemetry Payload Binding

### 5.1 Mathematical Coordinate Frame Transformations
- **Swarm 2D Cartesian to ROS 2 ENU (East-North-Up)**:
  $$X_{ENU} = X_{recon}, \quad Y_{ENU} = Y_{recon}, \quad Z_{ENU} = Z_{recon} = 10.0\text{m}$$
  $$V_{x,ENU} = V_{x,recon}, \quad V_{y,ENU} = V_{y,recon}, \quad V_{z,ENU} = 0.0$$
- **Swarm 2D Cartesian to MAVLink Local NED (North-East-Down)**:
  $$X_{NED} = Y_{recon} \quad (\text{North})$$
  $$Y_{NED} = X_{recon} \quad (\text{East})$$
  $$Z_{NED} = -Z_{recon} = -10.0\text{m} \quad (\text{Down})$$
  $$V_{x,NED} = V_{y,recon}, \quad V_{y,NED} = V_{x,recon}, \quad V_{z,NED} = 0.0$$
  $$\theta_{NED} = \frac{\pi}{2} - \theta_{recon} \pmod{2\pi}$$

#### Matrix Transformation (Swarm Recon -> MAVLink Local NED):
$$\begin{bmatrix} X_{NED} \\ Y_{NED} \\ Z_{NED} \end{bmatrix} = \begin{bmatrix} 0 & 1 & 0 \\ 1 & 0 & 0 \\ 0 & 0 & -1 \end{bmatrix} \begin{bmatrix} X_{recon} \\ Y_{recon} \\ Z_{recon} \end{bmatrix}$$

### 5.2 Target Detection & Encirclement Standoff Orbit Logic
When a drone detects a target at position $(T_x, T_y)$:
1. Broadcast `TargetTelemetry` payload (`target_id`, `position`, `confidence`, `timestamp`, `detecting_drone_id`, `standoff_radius`).
2. Swarm agents ingest the packet via ROS 2 / SDK adapter and transition operating mode from `VORONOI_SEARCH` to `TARGET_ENCIRCLEMENT`.
3. Compute tangential orbit waypoint around target position maintaining standoff radius $R_{standoff} \in [10\text{m}, 20\text{m}]$ (default 15.0m) with multi-drone phase spacing offset:
   $$\theta = \operatorname{atan2}(Y_{drone} - T_y, X_{drone} - T_x) + 0.3 + \frac{2\pi \cdot \text{drone\_id}}{N_{drones}}$$
   $$W_x = T_x + R_{standoff} \cdot \cos(\theta), \quad W_y = T_y + R_{standoff} \cdot \sin(\theta)$$
4. Apply Rotational APF force vector offset from active `ThreatZone` fields to guarantee hazard clearance during orbit.
5. Export navigation target $(W_x, W_y)$ via MAVLink `SET_POSITION_TARGET_LOCAL_NED` / `MAV_CMD_NAV_WAYPOINT` and ROS 2 `~/nav_waypoint`.
6. Target Clearance & Reversion: Calling `trigger_target_cleared()` publishes a target telemetry packet with `cleared = True`, resets `active_target = None`, reverts `operating_mode` to `VORONOI_SEARCH`, and updates underlying `SwarmAgent` back to `SEARCH` mode.
